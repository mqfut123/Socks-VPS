# Socks-VPS v1.0.3 handoff

日期：2026-07-26
来源：tag `v1.0.3`、commit `8abebd8`、GitHub Release 和 Ubuntu VPS
验收记录；历史回填。

## 根因与修复

Ubuntu 22.04 的 nftables JSON 输出保留 set 注释，但省略 table 和 chain
注释。v1.0.2 依赖 table 注释判断所有权，停止或替换规则时会把自有表误判
为外部资源。

v1.0.3 将固定所有权标记放在 `ip/socks_vps/cn_ipv4` set 注释上，并同时
核对 family、table 和 set name。缺少精确标记的同名表继续视为外部资源，
安装器不会替换或删除。

## nftables 生命周期

- 防火墙 unit 加入原生 `nftables.service` 的 stop/restart 和 reload
  传播关系。
- 原生 reload 后重新应用项目表。
- 规则重建失败时异步停止主服务，避免 SOCKS 监听长期存在而 CN 规则缺失。
- remove 不依赖配置和 zone 仍然可读，故障状态下也能撤销自有表。
- 原生 nftables 原先 inactive 时，运行中启用应使用 restart，而不是单独
  start。

## 其他修复

- 无 WARP unit 时不再把 systemd 的空查询状态显示成错误警告。
- Linux 集成测试的 nft counter 读取不再因 `pipefail` 和 awk 提前退出得到
  状态 141。

## Ubuntu 22.04 amd64 验收

- 自动端口安装、认证、公网 IPv4 出口及 SOCKS 命令/地址边界。
- 模拟 CN 来源 SYN drop，非 CN 来源进入认证。
- UFW enable/reload/deny/恢复，确认项目规则不绕过主机防火墙。
- nftables reload/restart/stop、规则重建失败停服、开机启动。
- 主进程异常退出、端口冲突、错误配置、更新、卸载、恢复和重启。
- 三轮各 256 条 TCP 隧道、256 条慢握手和活动连接停服清理；峰值 RSS
  约 10.7 MiB、cgroup 内存约 13.2 MiB，未观察到持续增长。
