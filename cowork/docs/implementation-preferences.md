# Socks-VPS 实现与交付偏好

本文档是 Socks-VPS 的长期实现偏好。变更产品边界前先确认目标用户、SOCKS 的角色、流量方向、认证方式、监听范围和管理边界。

## 1. 与 WARP VPS Manager 共存

Socks-VPS 可能与 WARP VPS Manager 安装在同一台机器，但两者是完全独立的项目。

以下 WARP VPS Manager 资源均视为外部资源：

- `warp-vps*` systemd 服务和定时器
- `warp-vps-wg` 网卡
- `table inet warp_vps` nftables 表
- `/opt/warp-vps-manager`
- `/etc/warp-vps-manager`
- `/var/lib/warp-vps-manager`
- `/var/backups/warp-vps-manager`
- `/usr/local/bin/warp-vps`

Socks-VPS 必须使用独立的命名空间、端口、服务、配置、运行目录、日志和防火墙对象。实际名称在产品入口确定后统一决定，不预先散落多套名字。

安装或变更网络前，先只读检查现有监听端口、systemd 服务、网卡、路由、策略规则和防火墙对象。发现冲突时返回准确的冲突资源，不停止另一个项目，也不自动换用另一套网络方案。

卸载只撤销 Socks-VPS 自己创建或有明确接管记录的资源。共享系统包和另一个项目使用的依赖不得因 Socks-VPS 卸载而被删除。

以上共存与所有权要求属于内部实现约束，不在常规安装、重装、更新或卸载文案中逐项自证。只有真实冲突会影响当前操作时，才向用户显示具体冲突资源、实际影响和可执行动作。

## 2. 系统适配

首要目标是使用 `systemd` 的 Linux VPS：

- Debian、Ubuntu 及其他使用 APT 的系统
- Fedora、RHEL、CentOS、Rocky Linux、AlmaLinux 及其他使用 DNF/YUM 的系统
- 优先验收 `amd64` 与 `arm64`

按当前机器的真实能力选择路径，不维护没有官方依据的发行版版本白名单。系统支持结论来自包管理器、systemd、内核网络能力和锁定依赖的官方发布范围。

架构支持必须逐项核对所需二进制的官方构建产物；没有可用产物时明确停止，不把其他架构包、非官方镜像或临时编译当作兼容方案。

IPv4、IPv6、双栈、NAT、转发和容器环境分别定义并验收。没有验收的组合不写成已支持。

## 3. 安装体验

- README 首屏顺序为：一条 Bash 安装命令、产品能力、最短使用入口、支持环境和管理方式。
- 公开安装入口只保留一条短的 `bash <(curl ...)` 命令，不展示 `curl | bash`、`pipefail` 包装、变量拼接或多套等价入口。
- 需要特权写入时才要求 `root`，只读命令不因后续写入需求而提前拒绝。
- 交互安装先收齐真实必需的选择，再开始安装依赖或改动系统。
- 在当前操作及其目标配置已确定后，只检查该操作真实需要的依赖：启动或验证
  监听时需要 `ss`；当前或目标配置存在大陆阻断、需要撤销自有阻断表或执行卸载
  所有权检查时需要 `nft`；`ip` 不是生产依赖。缺少依赖时先列出实际需要安装的
  发行版包，再以 `[Y/n]` 询问；回车确认继续，`n/N` 在包管理器写入前取消。
- 用户明确指定的端口、监听地址、认证方式和上游地址保持原样；仅在用户选择“自动”时自动分配。
- 再次运行安装入口应识别当前状态并进入明确的管理、更新或重装流程，不重复创建资源。
- 用户可见的安装、管理、状态和错误文案使用中文；命令名、JSON、退出码和供程序消费的数据格式保持稳定。
- 交互终端用青色信息、黄色进行中、绿色成功和红色失败区分阶段；非 TTY、管道和日志只输出普通文本，不添加动画、后台进度或额外状态。
- 环境检查、安装包校验和服务自检按阶段合并显示。成功时不逐个打印 SHA-256 文件名或内部命令输出；失败时保留能定位当前问题的诊断。
- 下载、包安装和服务启动必须有清楚的进度与最终结果；不能把部分完成显示为安装成功。
- 安装、重装和更新成功后显示 `打开管理菜单：sudo socks-vpsctl`；失败时不显示。
- 状态、列表和连接信息按配置逐项显示名称、端口、用户名、密码和大陆来源设置，不依赖中英文字符等宽对齐。
- 需要选择 SOCKS 的交互操作中，只有一个配置时直接选中；多个配置时按
  `1、2、3…` 列出并要求输入序号，不要求输入配置名称。公开子命令仍允许
  使用配置名称参数直接指定目标。
- 菜单将 `credentials` 展示为“修改连接设置”，公开子命令保持不变。选定 SOCKS
  后依次询问是否修改大陆来源阻断、用户名和密码，各项默认不修改；选择大陆来源
  阻断后使用 `[Y/n]`，回车或 `y` 阻断、`n` 不生成该端口的 Socks-VPS CN
  `drop` 规则；选择用户名或密码后，留空才生成对应的 20 位随机值。未选字段保持
  原值，没有选择或最终值未变化时不进入特权 apply、不检查依赖、不停服、不写配置。
- 连接信息只使用已确认的公网 IPv4；查询失败时要求用户填写，不把路由源地址或 NAT 私网地址当作公网地址。
- 常规成功文案只说明当前操作及结果，不列举未修改的外部项目、共享资源或内部
  防御边界，不使用项目对比来证明自身独立性。

## 4. 依赖与权威来源

- 优先使用发行版包、官方仓库、标准库和项目已锁定依赖。
- 同一依赖只保留一个权威安装来源。
- 不因包缺失自动切换到源码编译、第三方仓库、非官方二进制、HTTP 镜像或跳过签名校验。
- 不把 WARP VPS Manager 已安装的 Cloudflare WARP、WireGuard、redsocks 或 nftables 配置视为 Socks-VPS 可直接复用的项目状态。
- 确实需要共享系统级依赖时，记录资源所有权；卸载不猜测依赖是否可删除。

## 5. 不接受的兜底

- SOCKS 链路不可用时，不回落到 VPS 原生直连，不以避免报错为由暴露真实出口。
- 不静默切换 SOCKS 版本、传输协议、认证方式、DNS 解析位置、监听地址或上游节点。
- 指定端口冲突时不自动改端口；返回占用事实和可执行操作。
- 预定使用 nftables 时不静默改用 iptables，反之亦然。
- 不用固定等待窗口、无限重试、后台修复循环、marker、影子状态或双写掩盖失败。
- 不用宽泛 `try/catch`、`|| true`、默认值或旧配置回退吞掉契约错误。
- 不在无法确认服务、端口、路由或规则实际生效时打印成功。
- 外部依赖失败时保留准确错误；只有当前动作确实需要重试时，才提供人工重试入口。

## 6. 网络与安全边界

- 默认只监听完成当前需求所需的最小地址范围；公网监听必须是明确产品决定。
- 认证信息不出现在命令行、日志、Git、进程标题或可公开读取的配置中。
- DNS 由本地解析还是由代理端解析必须成为明确契约，不能根据失败结果自动切换。
- 防火墙、策略路由、默认路由和 DNS 的改动必须能直接回指当前产品需求。
- 所有网络写入先在一个权威边界生成完整目标配置，再原子启用；不在多个脚本中分散追加规则。
- 停止、更新、切换或卸载前先识别当前所有权；无法确认时停止写操作，不碰外部资源。

## 7. 生命周期

- 安装、启动、停止、重启、更新、重装和卸载使用同一套权威配置与状态判断。
- 健康检查只读核对配置、systemd、监听归属、认证和所需防火墙状态，不在检查过程中启用服务，也不接管系统或其他项目。
- 更新保持公开配置与命令契约；需要迁移时先以实际第二个用例证明迁移机制必要。
- `/usr/local/bin/socks-vps` 使用与当前 release 内容一致的普通文件，避免
  systemd 在 SELinux Enforcing 系统中从 release 树执行非标准标签文件。
- `add`、`credentials`、`remove`、`update` 和 `reinstall` 只在同一次操作内暂存原值。成功后立即删除临时副本；失败时恢复原位并清理，不创建持久快照、恢复脚本、marker 或第二套状态。
- `remove` 成功后永久删除目标配置；最后一个配置不单独删除，统一进入完整卸载。
- 重装在写入前明确说明全部现有 SOCKS 配置将永久删除，并只确认一次。
- 永久卸载在首次删除前一次确认当前 release、公开二进制、当前版本应有的管理命令和 systemd unit 的精确所有权；历史 v1.0.x 本身没有管理命令，只按其 VERSION 契约接受缺失。无法确认时停止，不删除相邻或同名外部资源。
- 卸载先停止并禁用 Socks-VPS 服务，验证自有监听和 `table ip socks_vps` 已撤销，再永久删除全部配置、版本、命令、unit、运行目录、历史备份以及专用用户和组。
- 共享系统包、外部同名 nftables 表、WARP VPS Manager 资源和其他项目数据不属于卸载范围。
- 下一次成功的特权生命周期操作清理旧版留下的 `/var/backups/socks-vps/`、非当前 release、`.migrated-*`、`.bind-failed-*` 及已知 pending/temp 项目残留。
- “清理日志”删除上述 Socks-VPS 自有历史和事务残留，不删除共享 journal，
  不重启服务，也不修改当前配置。

## 8. 验收与发布

本地检查覆盖语法、格式、静态分析、配置生成和纯函数逻辑。生产结论还需要干净 Linux VPS 上的真实验收：

1. 目标 APT 与 DNF/YUM 系统至少各一套。
2. `amd64` 与 `arm64` 分别核对依赖和运行行为。
3. 新装、重复运行、重启、更新、永久删除配置、重装和永久卸载。
4. 正常 SOCKS 请求、认证失败、上游不可达、端口冲突和 DNS 契约。
5. 服务状态、监听端口、路由、防火墙、DNS 与实际出口一致。
6. 与 WARP VPS Manager 同机运行，双方服务、端口、网卡、规则、更新和卸载互不影响；该约束通过测试证明，不写入常规用户文案。
7. 配置损坏时仍能按所有权移除自有 nftables 表；外部同名表保持不变。
8. 自动端口真实 bind 竞争最多重选一次，操作失败不留下临时配置、旧 release 或持久恢复数据。
9. 在同一公网 IP 和端口完成 `n → y → n` 验收：`n` 时大陆来源能够连接且无对应 Socks-VPS CN `drop`，`y` 时大陆来源被丢弃、非大陆来源仍可连接并有规则计数，切回 `n` 后恢复。
10. 全部配置允许大陆来源时覆盖无 nftables 的安装与生命周期；同版本更新和未修改连接设置均不得触发依赖安装或系统写入。

发布说明区分本地测试、CI、测试 VPS 与生产验收，不用 mock 或静态扫描替代真实网络结论。
