不停服、不写配置。

## 本轮问题与根因

此前 `credentials` 固定同时轮换用户名和密码，不能修改大陆来源设置。
大陆允许/阻断值虽然写入配置，但依赖和生命周期判断按动作粗粒度执行：
全允许配置仍可能被 nftables 前置检查阻断；部分 add/remove 路径又可能在
写配置后才发现 nftables 不可用或同名表不属于本项目。卸载结果还包含与
用户当前操作无关的共存说明。

本轮将最终实例集合设为唯一决策来源：

- 只有当前或目标实例需要大陆阻断、需要撤销自有阻断表，或执行卸载范围
  检查时才要求 `nft`。
- 只有需要启动或确认监听时才要求 `ss`；生产路径不再要求 `ip`。
- 所有实例都允许大陆来源时，不创建项目 nftables 表；`nft` 缺失或命令
  存在但不可用均不阻止合法的安装、更新和连接设置修改。
- 真实需要 `nft` 或 `ss` 时，在事务写入和停服前验证命令可执行性及
  资源所有权，失败时保持配置、服务、当前版本和防火墙不变。
- 用户可见的卸载与清理结果只陈述 Socks-VPS 当前动作和结果。

## 当时产品与资源边界

- 一个 Go 进程读取 `/etc/socks-vps/instances/*.json`，运行多个独立
  SOCKS5 配置。
- 只支持 IPv4、RFC 1929 用户名/密码认证和 TCP `CONNECT`。
- CN 来源阻断由 `table ip socks_vps` 在 TCP 握手前执行；Go 服务不重复
  判断。
- 配置、端口、凭据和 `allow_cn` 只以实例 JSON 为权威。
- 当前版本链接：`/usr/local/lib/socks-vps/current`
- 程序入口：`/usr/local/bin/socks-vps`
- 管理入口：`/usr/local/bin/socks-vpsctl`
- 服务：`socks-vps.service`、`socks-vps-firewall.service`
- 防火墙所有权：`table ip socks_vps` 及带项目注释的 `cn_ipv4` set

## 当时交互与生命周期约定

- 安装、更新和重装在开始系统写入时执行完整安装包校验；实例管理和卸载只
  检查当前动作真正需要的资源和所有权。
- `add`、`credentials`、`remove`、`update` 和 `reinstall` 只在同
  一次操作内暂存原值；失败时恢复，成功后立即清理。
- `remove` 永久删除目标配置；最后一个实例通过 `uninstall` 删除。
- `status` 是只读综合检查，不启用服务。
- 凭据、测试机地址和 SSH 信息不得写入 Git、handoff、日志或发布包。
