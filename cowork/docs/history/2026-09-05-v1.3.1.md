## 本轮审查结论

现有单进程、多实例 JSON、独立 nftables 表的实现适合当前 IPv4 TCP SOCKS 用途。
本轮沿 bootstrap、配置加载、认证、目标过滤、拨号、双向转发、状态检查、安装、
更新、配置修改、删除、事务恢复、卸载和发布包检查完成源码审查，并对发现的四处
问题先复现再修复。

| 问题与触发 | 根因 | 本轮修复 |
|---|---|---|
| 客户端或目标端 TCP RST 后，另一端一直保持连接 | relay 丢弃 io.Copy 错误，仍等另一方向完成 | 实际复制错误关闭双方；正常 EOF 保留 CloseWrite |
| 域名首个公网 IPv4 不响应，后续可达地址没有机会尝试 | 所有 numeric-IP 拨号共用截止时间，第一个消耗全部预算 | 既有循环分配剩余时间；单次 2 秒下限仍由总期限裁剪 |
| 认证自检失败仍显示监听与认证正常，或通过启动/恢复验收 | Bash 条件调用抑制 errexit，self-check 失败后继续检查端口 | 两种配置入口显式传递 self-check 失败 |
| nft 查询失败被当作自有表已撤销 | 对 nft 查询退出码直接取反 | 复用既有 capture_existing_table，确认 absent 才成功 |

生产代码修改仅为 [`internal/server/server.go`](../../../internal/server/server.go)、
[`scripts/install.sh`](../../../scripts/install.sh)、[`scripts/firewall.sh`](../../../scripts/firewall.sh)。
公开命令、配置 schema、依赖、监听范围、CN 选择及资源所有权沿用当前契约。

README 使用 natural-business-writing 与 copywriting 技能改写：首屏保留唯一稳定安装命令，
用安装即获得连接信息、多组独立端口与凭据、逐端口大陆控制、中文管理和更新保留设置
说明选择理由。保留既有管理命令和协议范围；IPdeny 数据本轮未更新。

多地址拨号遵循 [Go Dialer 的超时分配语义](https://pkg.go.dev/net#Dialer.DialContext)，
单次下限来自 [Go 1.26.3 partialDeadline](https://raw.githubusercontent.com/golang/go/go1.26.3/src/net/dial.go)。
保留一次 A 查询、只拨批准后的公网 IPv4、每个地址最多一次和解析加拨号的原总期限。

## 本地验证

- Go 1.26.3、macOS arm64：`go test -mod=readonly -race ./...`，6 个包、89 个顶层测试全部通过。
- `go vet ./...`、全部 Shell 脚本 `bash -n`、`git diff --check` 通过。
- 八组 Shell 回归：account_boundary、contracts、lifecycle_logic、listener_parser、
  firewall_logic、dependency_operability、connection_settings_logic、restore_state 全部通过。
- TCP RST 使用本机真实 TCP 双向复现；正常 EOF 后的 73 KiB 响应完整转发。
  RST 定向回归重复 10 次通过。
- 多地址拨号使用可控 dialer：首地址真实等待子期限超时后，第二地址成功；
  父取消不继续拨号，短父期限不延长。

- 完整 ShellCheck 当前仍有历史告警；修改的 install.sh 与基线均为 5 项，
  firewall.sh 为 0 项，没有新增生产脚本告警。未关闭或修改 lint 规则。
