## 当时产品边界

- 独立 Go 服务，不使用 Xray 运行时。
- 一个进程读取 `/etc/socks-vps/instances/*.json`，运行多个独立 SOCKS
  配置。
- 监听 `tcp4` 和 `0.0.0.0:<port>`。
- 只支持 SOCKS5、RFC 1929 用户名/密码认证和 TCP `CONNECT`。
- 域名只解析 A 记录，出站只使用 `tcp4`。
- 拒绝 IPv6、UDP、BIND、私网、本机、链路本地、云元数据和其他
  IPv4 特殊用途目标。
- CN 来源由 `table ip socks_vps` 在 TCP 握手前丢弃；Go 服务不重复判断
  CN 来源。
- 未命中的数据包继续经过主机已有 nftables、UFW、firewalld 和云防火墙，
  项目不添加全局 accept。
- WARP VPS Manager 的服务、网卡、路由、配置和 `table inet warp_vps`
  始终是外部资源。

## 权威状态与资源

- 配置：`/etc/socks-vps/instances/*.json`
- 当前版本链接：`/usr/local/lib/socks-vps/current`
- 版本目录：`/usr/local/lib/socks-vps/releases/<version>`
- 程序入口：`/usr/local/bin/socks-vps`
- 管理入口：`/usr/local/bin/socks-vpsctl`
- 服务：`socks-vps.service`、`socks-vps-firewall.service`
- 防火墙：`table ip socks_vps`
- 所有权标记：`cn_ipv4` set 注释 `Socks-VPS managed CN IPv4 set`

每个端口、凭据和大陆来源设置只以对应实例配置为权威。手动端口冲突时
显示占用者并停止；自动端口以服务真实 bind 结果为准，只有新选端口发生
竞争时重选一次。

`/var/backups/socks-vps/` 不再是当前状态来源。下一次成功的特权生命周期
操作会清理旧版持久备份、非当前 release、`.migrated-*`、`.bind-failed-*`
及已知 pending/temp 残留。

## 候选生命周期

- 安装、更新和重装只在开始系统写入时执行完整安装包校验；实例管理和卸载
  只检查当前动作需要的运行资源和所有权。
- `add`、`credentials`、`remove`、`update` 和 `reinstall` 仅在同一次
  操作内暂存原值；失败时恢复，成功时立即清理，不保留 snapshot、marker
  或 `restore` 命令。
- `remove` 永久删除目标配置，最后一个实例仍必须通过 `uninstall` 删除。
- 重装永久替换全部实例配置，并在首次写入前明确确认。
- 卸载在首次删除前确认当前 release、公开二进制、当前版本应有的管理命令
  和 unit 的精确所有权；历史 v1.0.x 本身没有管理命令，只按其 VERSION
  契约接受缺失。随后停止并禁用服务、撤销自有监听和 nftables 表，永久
  删除全部项目文件、历史备份、运行目录以及专用用户和组。
- 共享系统包、外部同名 nftables 表和所有 WARP VPS Manager 资源保持不变。
- 防火墙 `remove` 不读取实例配置或 IPdeny 数据；配置损坏不能阻止删除
  已确认归属本项目的表。
- `status` 是只读综合检查，覆盖配置、systemd、监听归属、认证和所需
  防火墙状态，不在检查中启用服务。

## 已有验证与本轮验收边界

`v1.1.0` 发布时已完成 Go race/vet、Shell 与集成生命周期门禁、两个架构
的可复现发布包和校验，并在 CentOS Stream 9 实测更新、多配置流量、CN
nftables、凭据轮换、端口冲突、systemd 重启、TCP keepalive、快照恢复、
可恢复卸载和重启。

其中快照恢复与可恢复卸载属于 `v1.1.0` 历史行为，不能证明当前候选的永久
删除路径。

当前候选已通过 Bash 语法、Go test/vet/race/gofmt、6 项本地集成契约、
双架构 `check-release`、`check-public-release`、`package_test` 和可复现
重建。临时 `1.2.0-rc.2` 产物哈希：

- `install.sh`：`119e13ec9c19f73d1ee8db541c4bde1bf6b1a590d59ddb373e6f79b871c4a0bf`
- `amd64`：`58b290854d2e7b6876fec084e308f0e2bd97814651f8e119a8d36dabb6a09f26`
- `arm64`：`592cd90b13a30cc705f0ad214db0acf3c16ef3a33eb71e075162e907a38fb93d`

发布前仍需在可信的干净 Linux VPS 上覆盖多配置、更新、重启、真实 SOCKS
流量、配置损坏后的自有防火墙删除、端口竞争和永久卸载，并保存 systemd、
监听、nftables、实际出口以及卸载后资源不存在的证据。

## 当时交互与生命周期约定

- 交互终端显示青色信息、黄色进行中、绿色成功和红色失败；非 TTY、管道
  和日志只输出普通文本。
- 环境检查、安装包校验和服务自检按阶段合并；成功不逐个打印文件名，失败
  保留当前诊断。
- 公网 IPv4 查询失败时要求用户填写，不使用可能为私网的路由源地址。
- 凭据、测试机地址和 SSH 信息不得写入 Git、handoff、日志或发布包。
- 当时未完成新测试环境的身份核验，因此没有增加远端验收或正式发布结论。
